# 30-day launch plan

**Goal:** ten completed audits, three real collaboration conversations and one clear paid offer. Not virality.

**Assumption:** one person, a few hours a day, no ad budget. If you have less time, use the one-hour version at the bottom.

## Week 1 — make the front door obvious

| Day | Action | Done when |
| --- | --- | --- |
| 1 | Audit the three live pages with LaunchGrade; fix every fail, keep the intentional warnings. | Reports are linked and dated. |
| 2 | Publish the before/after page: B- 71 → A+ 100, with both reports. | A stranger can click both. |
| 3 | Rewrite the LaunchGrade README first screen: what it does, one command, one real result. | The command works from a clean folder. |
| 4 | Publish `FastPress Start` (or the smallest useful template) with an A+ report. | A stranger can fork and edit it in 15 minutes. |
| 5 | Add the GitHub Action to Marketplace and a sample workflow. | The action appears in Marketplace search. |
| 6 | Submit the MCP server to two directories with a 30-second demo. | Two submissions confirmed; rules followed. |
| 7 | Set up the scorecard in [measurement.md](measurement.md); record the baseline. | Numbers have dates and sources. |

**Week 1 output:** a page worth sharing, a tool worth trying, and a way to tell whether either worked.

## Week 2 — publish three teardowns

Pick three public launch pages in adjacent niches. Do not pick competitors. Do not criticize people; critique the page.

For each teardown:

1. Run LaunchGrade and save the report.
2. Choose the three fixes with the highest impact.
3. Write 400–600 words: what works, what to fix first, what not to change.
4. Publish on the site with a date and a public URL.
5. Share one concrete lesson, not the score alone.

| Day | Action |
| --- | --- |
| 8 | Teardown 1: a solo-founder page with a clear offer. |
| 9 | Teardown 2: a developer tool with strong docs and a weak CTA. |
| 10 | Teardown 3: a page that is beautiful but invisible to agents. |
| 11 | Turn each into a short X/LinkedIn post with one screenshot and one lesson. |
| 12 | Post the best one to Indie Hackers or dev.to; answer every comment. |
| 13 | Send two personalized audit offers using [outreach-emails.md](outreach-emails.md). |
| 14 | Review: which teardown got a reply, not just a like? |

**Week 2 output:** three permanent artifacts and the first real conversations.

## Week 3 — ask, carefully

No mass email. Twenty personalized messages is the ceiling for the week; ten is better.

| Day | Action |
| --- | --- |
| 15 | List 20 public launch pages with a specific, fixable issue. Verify each issue yourself. |
| 16 | Send 5 audit offers. One paragraph, one specific observation, one free report. |
| 17 | Send 5 collaboration emails to maintainers of adjacent open-source tools. |
| 18 | Pitch 3 newsletters or podcasts with a concrete angle, not "please feature us". |
| 19 | Follow up once on Monday's messages. No guilt, no "bumping". |
| 20 | Publish a Ship Log: what shipped, one sourced number, one lesson. |
| 21 | Run the first free audit clinic or a live teardown; record it. |

**Week 3 output:** replies, not reach. Track sends, replies, audits and calls separately.

## Week 4 — convert without pressure

| Day | Action |
| --- | --- |
| 22 | Deliver the audits. Send the report, the top three fixes and an offer to answer questions. |
| 23 | Ask two happy recipients for a specific, attributable quote. If they decline, move on. |
| 24 | Write the repeatable offer: scope, deliverables, price range, timeline, what is not included. |
| 25 | Publish it as a page. No fake scarcity, no countdown. |
| 26 | Follow up with collaboration conversations; propose one small joint artifact. |
| 27 | Publish teardown 4 or a "what we learned from 10 audits" post. |
| 28 | Review the scorecard. Kill the channel that produced nothing. |
| 29 | Plan the next 30 days around the one channel that produced a real reply. |
| 30 | Publish the honest recap: what worked, what did not, what is next. |

**Week 4 output:** a scoped offer, a decision, and a public record.

## One-hour-a-day version

- **Mon:** ship one small improvement; link the commit.
- **Tue:** write one teardown or one useful post.
- **Wed:** send three personalized audit offers.
- **Thu:** send three collaboration emails.
- **Fri:** follow up once; update the scorecard.
- **Sat:** 30 minutes: answer replies, fix one confusing thing.
- **Sun:** off. Rest is part of the plan.

## What not to do

- Do not ask for upvotes, buy stars, or join engagement pods.
- Do not send the same email to 100 people with a first-name merge.
- Do not publish a "customer" who has not agreed to be named.
- Do not announce a partnership before the artifact exists.
- Do not add analytics to a page that promises no analytics. Use form source fields and GitHub referrers.
- Do not call a like a lead.

## Kill criteria

At day 30, stop a channel if it produced **zero replies after 20 genuine attempts**. Do not blame the algorithm. Change the offer, the audience or the message.

At day 90, see [GOALS.md](../GOALS.md) for the paid-pilot decision.
